# 部署文档

内网点餐系统（后台 + 员工 Web + 管理中台 + Android），仅限本地内网使用，无数据库。

## 一、构建环境

| 工具 | 版本要求 | 说明 |
|---|---|---|
| JDK | 17+ | 构建 server / android（编译目标 17） |
| Node.js | 20+ | 构建 web / admin |
| Android SDK | API 34 + build-tools 34.0.0 | 仅构建 android 需要 |
| Gradle | 8.9 | 由仓库内 wrapper 自动获取，无需手动安装 |

```bash
# 按你的实际安装位置配置（示例）
export JAVA_HOME=/path/to/jdk17
export ANDROID_HOME=/path/to/android-sdk
export PATH="$JAVA_HOME/bin:/path/to/node/bin:$PATH"
```

> `scripts/check-all.sh` 与 `scripts/build-all.sh` 会自动探测工具链：
> 优先使用已设置的 `JAVA_HOME` / `ANDROID_HOME` / PATH 中的 node；
> 其次尝试加载可选的本机工具链约定 `~/tools/env.sh`，并探测 `~/.jdks/`、`~/tools/` 下的 JDK。
> 任选一种方式配好即可。

## 二、开发模式

```bash
# 1) 后台（8080，首次启动自动种子初始化账号）
cd server && ./gradlew bootRun

# 2) 员工 Web（5173，/api 已代理到 8080）
cd web && npm install && npm run dev

# 3) 管理中台（5174，/api 已代理到 8080）
cd admin && npm install && npm run dev

# 4) Android：Android Studio 打开 android/ 目录，或
cd android && ./gradlew :app:assembleDebug
# APK: android/app/build/outputs/apk/debug/app-debug.apk
```

单测一键全跑：`bash scripts/check-all.sh`

## 三、生产部署（单 jar 托管全部）

```bash
bash scripts/build-all.sh          # web/admin dist 拷入 server 静态目录并打 bootJar
LUNCH_DATA_DIR=/var/lib/lunch-order \
LUNCH_JWT_SECRET='<一段足够长的随机字符串>' \
  java -jar server/build/libs/server-*.jar
```

- 员工端：`http://<内网IP>:8080/`
- 管理中台：`http://<内网IP>:8080/admin/`（与员工端共享 cookie `lunch_token`，一次登录两端通用）
- **SPA 回退**：非 `/api/` 的未知路径分别转发到 `/index.html` 与 `/admin/index.html`（决策 D-006），刷新子路由不会 404。

## 四、Android 安装与通知

1. 安装 APK 后进入「设置」页，把服务器地址改为 `http://<内网IP>:8080`，点「测试连接」（收到任意 HTTP 响应即视为可达）。
2. 首次启动/进入主界面会请求通知权限（Android 13+）；Android 12+ 如精确闹钟被系统关闭，按提示去系统设置授权「闹钟和提醒」。
3. 默认每天 **17:30** 本地通知「今天需要点餐吗？请在 18:00 前登记」，可在设置页改时间或关闭；重启手机后自动恢复（BootReceiver）。

## 六、运维

- 数据备份/恢复/重置：见 `docs/数据说明.md`；重置脚本 `scripts/reset-data.sh`。
- 常见问题：
  - 提交点餐返回 2001 → 当前不在 [14:00, 18:00] 窗口（以服务器时间为准）；
  - 打开页面跳登录 → token 过期（7 天）或密码已修改（pwdVer 失效机制），重新登录即可；
  - 中台 403 → 当前账号不是 ADMIN。
